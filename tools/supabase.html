Supabase

読み方は「スパベース」。サイトの裏側でデータを管理する場所です。会員情報や投稿内容などを保存します。

ひとことで言うと

Supabaseは「Webサイト本体」ではなく「裏側のデータ管理」です。この言い方をすると、お客様にいちばん早く伝わります。

たとえば会員制サイトなら、画面の見た目は Netlify が配り、その画面に表示される会員名や投稿内容はSupabaseから取ってきています。

Supabaseは Cursor → GitHub Desktop → GitHub → Netlify の流れの外にあります。Cursorでコードを直しても、Supabaseの中のデータは変わりません。逆に、Supabaseのデータを直してもコードは変わりません。別々に扱います。

何を持っているか

Table Editor（データ）

表計算ソフトのような画面で、実際のデータが並びます。

  • 会員一覧、投稿、予約、問い合わせなど
  • 1行 ＝ 1件。列 ＝ 項目
  • 本番のデータもここに入っている

Authentication（ログイン）

誰がログインできるかを管理します。

  • メールアドレスとパスワードの登録
  • パスワード再設定のメール送信
  • ログインできない相談は、まずここを見る

触るときの決まりごと

場面 やること
本番データを直す 実装リードの確認を取ってから。1人で判断しないコードと違い、消したら履歴から戻せません
列や表を増やす 先に検証環境で試す。本番に直接入れない
お客様に画面を見せる 他のお客様のデータが映り込んでいないか確認する
接続キーを扱う コードに直書きせず、環境変数に入れる。Netlify 側にも同じ値を設定する

GitHubは間違えても履歴から戻せますが、Supabaseの本番データは戻せません。この2つは危なさの種類が違う、と覚えてください。

お客様への説明例

こう言う

  • 「サイトで使うデータを保管している場所です」
  • 「会員情報や投稿内容はここに入っています」
  • 「見た目とは別に、データだけを管理しています」

避ける言い方

  • 「BaaSでPostgreSQLが…」（伝わりません）
  • 「サイトが入っている場所です」（Netlifyと混ざります）
  • 「無料なので大丈夫です」（件数が増えると有料です）

困ったとき

起きたこと どうするか
ログインできない Authentication にそのユーザーが登録されているか見る
データが画面に出ない Table Editor に行があるか → 権限設定（RLS）で止まっていないか
公開したらデータだけ出ない Netlify 側に接続キーを設定し忘れていないか

次に進む合図

  • 本番データを直す前に、実装リードの確認を取った
  • 接続キーをコードに直書きしていない
  • お客様に見せる画面に、他社のデータが映っていない
前③ GitHub 次⑤ Netlify
