# SHINJIDAI 案件の進め方

新しい案件が入ってから、保守までの社内向け手順です。工程名と順番は [開発体制・品質管理](https://shinjidai.co.jp/development-process) と同じにしています。

## 見る

`index.html` を開くか、次でローカル表示します。

```bash
npm run dev
```

http://localhost:8080

## 構成

| ファイル | 中身 |
| --- | --- |
| `index.html` | 6工程の一覧、いつ何を確定させるか、進め方の特徴、担当 |
| `phases/01-hearing.html` | 聞くこと（業務・データ・制約・成功条件）、範囲の切り出し方 |
| `phases/02-requirements.html` | キックオフMTG、文書化する5つ、機能一覧の書き方とGitHub Pagesでの公開手順、完了定義 |
| `phases/03-contract.html` | 見積書のつくり方、摘要に並べる行、契約で決めること |
| `phases/04-development.html` | デザインと開発の同時進行、初稿提出→修正→テスト、変更の締め切り、検収 |
| `phases/05-production.html` | 4つの準備、切替の日の確認、引き渡すもの |
| `phases/06-maintenance.html` | 保守契約で決めること、依頼の分け方 |
| `tools/index.html` | 使う5ツールをローカル / クラウドに分けた全体像、言い換え表、切り分け表 |
| `tools/cursor.html` | 画面の見方とMacのキー、AIの頼み方、保存忘れの注意 |
| `tools/github-desktop.html` | プル（取る）・コミット（保存）・プッシュ（送る）、Cursorの開き方、コミット名の書き方 |
| `tools/github.html` | コードの保管庫。用語、履歴、Private運用、GitHub Pages |
| `tools/supabase.html` | 裏側のデータ管理。本番データを触るときの決まりごと |
| `tools/netlify.html` | 公開と自動反映。Deploysの見方、環境変数、戻し方 |

各ページの構成は「見出しの説明文（公開ページと同じ文）→ その工程でやること → 次に進む合図」です。書式を埋めるテンプレートは置かず、文章・表・写真だけで読めるようにしています。工程ごとの説明文は [開発体制・品質管理](https://shinjidai.co.jp/development-process) と同じ文にしているので、お客様への説明と社内の手順がずれません。

キックオフMTGは 02 要件定義の入口、検収は 04 開発・検証の出口です。工程は増やしません。デザインと開発は同時に進め、初稿提出 → 修正・改善 → 動作テスト・検収の順に確定させます。変更はリリース日から逆算して1か月半前まで（小さい案件は2週間前まで）。

## 画像

`img/` はAIで生成した写真です。各工程の見出しにその工程の場面、02に書類の整理、04に仕様変更の振り分けと検収、05に操作説明、トップに全体の流れとヒーロー画像を置いています。

`img/step-*.png` は操作手順の実画面です。GitHubのPages設定と、NetlifyのDeploys（成功・失敗・ログ）を置いています。手順が変わったら撮り直します。

`img/logos/` は各ツールの公式ロゴ（SVG）です。`tools/` の各ページと、04・トップのツール一覧カードで使っています。

写真のトーンは「ネイビー寄りの寒色、彩度低め、顔は写さない（後ろ姿や手元中心）」で揃えています。文字は入れません（生成すると日本語が崩れるため）。説明は必ず `figcaption` に書きます。描き足すときは既存の写真を参考画像に渡すと色味が揃います。
